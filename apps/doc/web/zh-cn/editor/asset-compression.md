# 资产压缩

编辑器可以把纹理和网格以压缩形式发布：纹理压缩为 **KTX2**（Basis Universal），网格压缩为**量化并经 meshopt 压缩**的二进制 `.zmsh`。压缩既能减小玩家的下载量，也能减少 GPU 显存占用。

压缩需要**显式开启**：只有设置里要求压缩的纹理和网格才会被压缩，因此更新引擎或编辑器不会改变已有项目的发布结果。源文件始终不会被修改，编辑器会另外生成压缩副本。

---

## 开启压缩

### 导入模型时

导入对话框中有两个选项，**默认都不勾选**：

| 选项 | 作用 |
| --- | --- |
| **Compress Textures** | 将模型的纹理标记为需要压缩 |
| **Compress Vertices** | 将模型的网格标记为需要压缩 |

这两个选项只影响本次导入新生成的资产。已经有设置的纹理和网格会保留原设置，所以重新导入模型不会覆盖你手动调过的设置。

### 已有资产

在**资产视图**中右键点击资产：

- 图片文件：**Texture Settings...**
- `.zmsh` 网格：**Mesh Settings...**

两者都支持多选。多选时只会写入你改动过的字段，例如给二十张纹理统一设置最大尺寸，不会改变每张纹理各自的用途。

## 纹理设置

| 设置 | 含义 |
| --- | --- |
| **Usage** | 纹理的用途：Color（sRGB 颜色）、Normal Map（法线贴图）、Mask / Linear Data（遮罩或线性数据）、HDR、UI。决定色彩空间和默认的压缩方式 |
| **Compression** | **Auto** 按用途自动选择；**ETC1S** 体积最小；**UASTC** 质量最高；**None** 发布源图 |
| **Quality** | 在压缩质量和文件体积之间取舍 |
| **Max Size** | 大于该尺寸的纹理会被缩小 |
| **Generate Mipmaps** | 压缩时生成 mipmap |

导入模型时，每张纹理的用途由引用它的材质槽决定：法线槽里的纹理是法线贴图，sRGB 颜色槽里的是颜色纹理，其余数据是遮罩。以其他方式加入项目的图片按文件名判断（识别 `_normal`、`_nrm`、`_orm`、`_roughness`、`_ao` 等后缀）。如果判断有误，请手动修正，用途会直接影响压缩质量。

选择 **Auto** 时，颜色纹理用 ETC1S，法线贴图和遮罩用 UASTC：法线贴图上的块状瑕疵会被光照放大，打包在一起的遮罩通道也会相互串色。

### ETC1S 和 UASTC 不是 GPU 格式

ETC1S 和 UASTC 是 Basis Universal 的存储格式。同一个 KTX2 文件适用于所有设备：加载时在后台 Worker 中转码为当前 GPU 支持的最佳格式（桌面 GPU 上是 BC7，移动端是 ETC2 或 ASTC，都不支持时退回未压缩的 RGBA8）。因此不需要按平台分别选择格式。

画质上限由存储格式决定：ETC1S 纹理转码成 BC7 后，看起来仍然是 ETC1S 的画质。

## 网格设置

| 设置 | 含义 |
| --- | --- |
| **Compression** | **meshopt**：顶点数据经量化后压缩存储；**None**：发布源网格 |
| **Normal Precision** | 法线精度：**12 bit**（默认）、**8 bit**、**16 bit** 或 **Keep float**（保持浮点） |

压缩对各顶点属性的处理：

| 属性 | 存储方式 |
| --- | --- |
| 法线、切线 | 八面体编码；12 位和 16 位存为 16 位整数，8 位存为 8 位整数 |
| 0–1 范围内的顶点色 | 8 位；超出该范围的 HDR 顶点色保持原样 |
| 骨骼权重 | 8 位，并重新归一化，保证每个顶点的权重之和仍精确为 1 |
| 位置、纹理坐标、骨骼索引 | 不变 |

顶点顺序始终保持不变，因此蒙皮、变形目标和几何缓存都能照常工作。

关于法线精度：8 位法线最大约有 0.8° 的误差，在面数较低的光滑表面（如车漆、陶瓷）上，会表现为明暗分界线不够平滑。12 位的误差约 0.05°，肉眼已无法分辨，因此作为默认值。在不在意这类误差的地方，8 位能最大程度节省显存。

编辑器图元编辑器中创建的参数化形状本身体积很小，始终按原样发布。

## 细节层次（LOD）

网格设置对话框里还可以为网格生成细节层次（LOD），让网格离相机远时改用简化版本。LOD 与压缩相互独立：只开 LOD 不开压缩也可以，这时派生副本里是未压缩的顶点数据加上各级索引。运行时如何选级见[细节层次（LOD）](zh-cn/mesh-lod.md)。

| 设置 | 含义 |
| --- | --- |
| **Levels of Detail** | LOD 级数，包含原始网格，最多 8 级。默认 1，即不生成 LOD |
| **Triangles Per Level** | 每一级保留上一级三角形的比例，默认 0.5 |
| **Pixel Error** | 自动切换距离允许的像素误差，默认 8。调大后会在更近处换到简化版本 |

生成方式：

- 每一级都从原始网格直接简化到目标三角形数（第 1 级为原始三角形数乘以比例，第 2 级乘以比例的平方，依此类推），使用 [meshoptimizer](https://github.com/zeux/meshoptimizer)。简化时考虑法线，并保留纹理接缝。
- 简化只生成新的索引，**顶点缓冲和顶点顺序不变**，所以骨骼网格和带变形目标的网格同样可以生成 LOD。骨骼数量不会减少。
- 再简化也不能减少三角形时，后面的级别不再生成，所以实际级数可能少于设置值。
- 每一级的切换距离由简化误差自动算出：在 1920 像素宽、90° 视角的画面上，这一级的误差投影后小于 Pixel Error 个像素时开始使用它。

只有三角形列表网格能生成 LOD，其他拓扑的网格忽略这些设置。

## 设置的存储位置

设置保存在资产旁边的 `.zmeta` 文件里：`rock.png` 对应 `rock.png.zmeta`。

- 资产视图中不显示 `.zmeta` 文件。在资产视图里重命名、移动、复制或删除资产时，对应的 `.zmeta` 会一并处理。
- 没有 `.zmeta`，或 `.zmeta` 无法读取的资产，一律不压缩。
- `.zmeta` 是编辑器数据，会保留在项目和项目导出中，但不会进入构建产物。

如果在编辑器之外移动或删除文件，请同时处理对应的 `.zmeta`。

## 后台压缩

压缩在后台进行：

- 打开项目时，所有需要压缩但还没有压缩副本的资产都会被加入队列。修改设置或修改源文件后，也会重新加入队列。
- 状态栏显示进度，例如 `Compressing assets 3/12: rock.png`。失败的数量也会显示在状态栏，具体原因见控制台。
- 编辑器本身加载的就是压缩副本，所以视口里看到的就是玩家实际看到的效果。

设置对话框最下面一行会显示资产的状态（网格设置对话框中写作 `Derived copy`，因为派生副本可能只是加了 LOD），例如：

```
Compressed copy: 2048.0 KB -> 683 KB, in use in the editor
```

**in use in the editor** 表示视口里显示的确实是压缩副本（压缩效果好的时候，肉眼很难和源文件区分）。**not loaded yet** 表示压缩副本已经生成，但当前场景仍在使用之前加载的版本，重新打开场景即可切换。

压缩副本缓存在项目的 `/.cache/derived` 目录下，以源文件内容、设置和编码器版本为键，没有变化的资产不会被重复压缩。这个目录在资产视图中不显示，也不会进入项目导出，可以随时删除，需要时会自动重建。

## 构建

执行 **Build Project** 时，需要压缩的资产发布其压缩副本，其余资产发布源文件，详见[构建与部署](zh-cn/editor/build-deploy.md)。场景和脚本中的引用仍然是源路径（如 `/assets/rock.png`）。构建会在 `asset-manifest.json` 中记录每个源路径对应的发布文件，引擎启动时会自动读取。

如果脚本绕过资源管理器、直接读取图片或网格文件（例如用 `fetch()` 或 `VFS.readFile()`），请把该资产的压缩方式设为 **None**，网格还要把 LOD 级数设为 1：有派生副本的资产，其源文件不会出现在构建产物中。

---

## 当前限制

- 只有 PNG、JPEG 和 WebP 图片能被压缩；TGA、HDR 和 EXR 图片按原样发布。
- 法线贴图按三通道压缩，尚未使用两通道的法线格式（BC5、EAC RG）。
- 网格的位置和纹理坐标不做量化。
- 已经打开的场景会继续使用之前加载的资产；修改压缩设置后，需要重新打开场景才能看到效果。
